ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Расширение бота MAX
1. Цель и контекст
Расширить существующего бота MAX (регистрация пользователей через ФИО, email, телефон) возможностью свободного диалога с языковой моделью через Ollama. Незарегистрированные пользователи не имеют доступа к чату — бот вежливо отказывает и предлагает пройти регистрацию. Каждый запрос и ответ модели записывается в SQLite с детализацией по токенам.
ℹ️  Регистрация (ФИО, email, телефон, MAX ID) уже реализована в базовом боте. Это расширение добавляет только AI-чат поверх существующей логики.
2. Логика доступа
Проверка при каждом текстовом сообщении:
Сообщение от пользователя
        │
        ▼
  users.max_user_id есть в БД?
   ├── НЕТ  → «Вы не зарегистрированы. Напишите /start»
   └── ДА   → Отправить запрос в Ollama → записать в chat_messages → ответить
⚠️  Проверка регистрации выполняется синхронно перед каждым обращением к Ollama. Никаких исключений — даже если пользователь был зарегистрирован ранее, а запись удалена.

3.4. Откуда берутся токены из ответа Ollama
Ollama возвращает метаданные в конце потокового ответа (поле done: true). Нужные поля:
// Финальный chunk при streaming (done: true)
{
  "done": true,
  "prompt_eval_count": 42,   // токены запроса (prompt_tokens)
  "eval_count": 156,          // токены ответа  (completion_tokens)
  "total_duration": 3200000000  // наносекунды → делим на 1e6 → мс
}
ℹ️  При использовании /api/generate вместо /api/chat поля называются так же. Если модель не вернула prompt_eval_count — сохранять 0.

5. История диалога (контекст)
5.1. Принцип формирования контекста
Перед каждым запросом к Ollama бот извлекает из таблицы chat_messages последние N пар (user + assistant) для данного пользователя и формирует массив messages:
# bot/ollama_service.py
def get_chat_history(max_user_id: str, limit: int) -> list[dict]:
    """Возвращает последние limit сообщений из chat_messages."""
    rows = db.execute(
        'SELECT role, content FROM chat_messages'
        ' WHERE max_user_id = ?'
        ' ORDER BY created_at DESC LIMIT ?',
        (max_user_id, limit)
    ).fetchall()
    # Разворачиваем — из DESC в хронологический порядок
    return [{'role': r, 'content': c} for r, c in reversed(rows)]
def build_messages(history: list, current_text: str) -> list[dict]:
    system = {'role': 'system', 'content': OLLAMA_SYSTEM_PROMPT}
    user   = {'role': 'user',   'content': current_text}
    return [system] + history + [user]
⚠️  CHAT_HISTORY_LIMIT = 10 означает 10 строк из БД (5 пар user+assistant). Увеличивать осторожно — каждое сообщение в истории увеличивает расход токенов.
5.2. Сброс истории
Команда /clear — очищает историю текущего пользователя (DELETE FROM chat_messages WHERE max_user_id = ?).
После очистки бот отправляет: «🗑️ История диалога очищена. Можете начать новый разговор.»
Команда /history — показывает последние 5 сообщений диалога (последние реплики).

7. Ключевые пользовательские сценарии
7.1. Незарегистрированный пользователь
Пишет любое сообщение боту.
Бот проверяет max_user_id в таблице users → запись не найдена.
Бот отвечает: «⛔ У вас нет доступа к чату. Для регистрации напишите /start»
Никакого запроса к Ollama не отправляется. Токены не тратятся.
7.2. Регистрация нового пользователя
Пользователь пишет /start.
Бот запрашивает ФИО → email → телефон (как в базовом боте).
При успешной регистрации: INSERT в users, переход в состояние CHAT.
Бот: «✅ Регистрация завершена! Теперь вы можете задавать вопросы — я отвечу с помощью ИИ. Напишите /help чтобы узнать о командах.»
7.3. Уже зарегистрированный пользователь
Пишет /start или любое сообщение.
Бот проверяет users.max_user_id → запись найдена.
Бот: «👋 Вы уже зарегистрированы. Просто задайте вопрос — я отвечу!»
Следующие сообщения обрабатываются в режиме чата.
7.4. Диалог с ИИ (happy path)
Зарегистрированный пользователь пишет вопрос.
Бот отправляет индикатор «печатает...» (typing action).
Бот формирует историю: последние CHAT_HISTORY_LIMIT записей из chat_messages.
Бот отправляет POST /api/chat в Ollama с системным промптом + историей + новым вопросом.
Ollama возвращает ответ + метаданные (токены, duration).
Бот сохраняет в chat_messages 2 записи:
role='user': content=вопрос, prompt_tokens из ответа Ollama, completion_tokens=0.
role='assistant': content=ответ, prompt_tokens=0, completion_tokens из ответа Ollama.
Бот отправляет ответ пользователю.
7.5. Ошибка Ollama (таймаут / недоступна)
POST /api/chat не отвечает за OLLAMA_TIMEOUT секунд.
Бот отвечает: «⚠️ Не удалось получить ответ от ИИ. Попробуйте позже.»
Запись в chat_messages НЕ создаётся (нет данных для записи).
Ошибка логируется через стандартный модуль logging.
